This revision aligns both skills with Preflight ruleset 1.7.0 and the live
submission form.

- Every Preflight finding is labeled on two axes: the published guideline
  sets the weight (a MUST is a Blocker or Required update, a recommended
  practice is a Suggested update) and match confidence decides whether it
  gates. Only a certain match produces changes_required; a probable match
  goes to Manual review (needs_review); a hint stays a suggestion.
- A syntax-tree pass confirms context the pattern match cannot see: whether
  window.open, a Designer write call, or getUserMedia runs at load or inside
  a click handler; whether a message handler reads event.origin; whether an
  http:// literal reaches a request helper. React DOM's resource hoisting no
  longer registers as script injection.
- Production-runtime checks (script pinning, SRI on the testing site) are
  runtime findings, not blockers. Fix them anyway; reviewers read them.
- The submission form now requires a Preflight receipt for new Apps and for
  updates that change code or scopes, and blocks a receipt that reports
  changes_required. Listing-only updates skip the receipt.
